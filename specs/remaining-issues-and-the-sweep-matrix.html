Purpose

Close every open defect in ccd-ia/featurizer — #27 and #36 (PR #43, waiting for the merge word), #38, #37, and two classes measured while this plan was written that have no issue yet — and stop the series. The defects are not arriving at random: each one sits in a combination of features that no test executes. The plan names those combinations as a matrix of seventeen cells, fills every cell with a registry-wide executing sweep, and adds a coverage test so that the next primitive, identifier role or render path cannot land outside it.

Problem

Why the count is growing. The tracker is two weeks old. Issue #2 is dated 2026-09-06, the day master became protected and "issue first" became the rule; before that date a defect became a commit, a TODO.org line or a paragraph in a session summary, so the earlier count is zero by construction. Twenty-two issues have been filed since. Nine are chores, docs or a feature request. Thirteen are defects, and they arrived in two bursts.

2026-09-07#7 #9 #12 #13The first consumer. triage-pg ran the library on shapes its author had not chosen: a wide table whose columns are named like featurizer output, a temporal: block on the other orientation, per-variable intervals.
2026-09-18 → 20#14 #18 #21 #23 #27 #29 #36 #37 #38Us, measuring. #23 and #29 came from the first sweeps that execute every registered primitive (83 transformers, 67 aggregations). #27 was measured before switching cdf on. #36, #37 and #38 were found while proving that the #27 fix holds on every render path. None was reported by a consumer.

Why they surface only now. None of the thirteen was introduced recently. Every one reproduces on the commit below its fix (3e1790d, de03142), in code that dates from 0.5 to 0.9. They stayed invisible because of how the suite is built. The testing guideline says to assert on SQL fragments and CTE names, and 762 of the 1,242 tests do exactly that: they render and never execute. The 480 that execute were each written for the shape their feature was designed around — plain lower-case column names, identity always in the transformer list, one as-of date, no interval on a materialized chain, a forced threshold of 1 in place of a real 1,664-column width. Every feature works on its own shape. The defects are all in the products: a primitive × a name shape, a whole-partition window × a child entity × a row after the as-of date, the TEMP-table path × two as-of dates × an interval. The golden-value and snapshot suites that enforce ADR-0015 pin what the engine does, so they pinned these too.

Why fixing one finds two. A fix to an invariant has to be shown to hold on all three render paths (single query, column groups, TEMP tables), and two of those paths had only narrow tests. Proving #27 on the TEMP-table path is what exposed #36 and #37. That is the instrument working, and it is also discovery by accident: which cell gets opened next depends on which bug happens to be under repair.

And one fix overshot. Since v1.2.0, #13, #24 and #29 quote a declared name byte for byte. Measured tonight: a config that spells a column totalAmount against a table created with unquoted DDL (PostgreSQL stores totalamount) runs on the v1.2.0 tag and fails on master c2c21a7 with column "totalAmount" does not exist. It is unreleased, and it has to be settled before any tag.

Solution

Treat the untested products as a finite list and work through it on purpose. Five invariants the engine promises — a primitive executes; it executes when a declared identifier is not a bare name; a row dated after the as-of date moves nothing; the three render paths agree; a config that validates runs — crossed with the things that vary: the transformer registry, the aggregation registry, the planner passes, the render paths, the identifier roles. That is seventeen cells. Seven are swept by the suite once PR #43 lands. Four are measured failing, two are measured clean with no test to keep them so, four have never been measured.

Each phase below is one class. It opens with its sweep, written first and watched red with a count; the fix follows; the sweep stays in the suite. Order is set by two constraints. A change to rendered SQL moves the same three pinned artifacts, so those phases are serialized and each one lands before the next is pushed. And the name rule (Phase 2) changes quote_if_bare, which every later quoting site goes through, so it goes first. The last engineering phase fills the cells that have no known failure, adds a test that each sweep parametrizes over the whole registry, and writes the rule into CONTRIBUTING.md. When a sweep turns up a class nobody has seen, the phase says what to do with it, so the plan cannot stall on its own success.

[x] Phase 2: A declared name means what it means in PostgreSQL

An unreleased regression, decided by the maintainer on 2026-09-20. Byte-for-byte quoting (#13, #24, #29) breaks a config that ran on v1.2.0 whenever the declared spelling and the stored column differ in case. The rule becomes PostgreSQL's own: a name that is a valid bare identifier is folded to lower case and then quoted (which also makes reserved words work); anything else is quoted byte for byte; a name the config already wraps in double quotes is taken exactly. One function changes. depends-on: Phase 1 merged (shared artifacts). owner: one worktree, planner/declared-name-rule.

'"entityId"' -> "entityId"        fails    runs     runs   (the YAML carries the quotes)

Questionables

[asked] #38 — what does a transformations: list without identity mean?

Carry raw inputs as helpers. A non-target transform also projects the raw columns its parent aggregates, so the SQL matches the feature set the planner and the manifest already produce. Rejected: aggregating only what was selected (planned features would leave the manifest), and rejecting the shape in validation (the shape stays unsupported). Phase 4.

[asked] What does a declared column name mean, now that byte-for-byte quoting broke a config that ran on v1.2.0?

PostgreSQL's own rule. A valid bare identifier folds to lower case and is then quoted; anything else is quoted byte for byte; a name already in double quotes is taken exactly. Every config that ran on v1.2.0 runs again with the same output names. The cost, accepted: a genuinely mixed-case column (pandas creates them) needs '"entityId"' in the YAML; it worked unquoted on master for the few days between #13 and this phase, and on no release. Rejected: keeping byte-for-byte and announcing a behaviour change. Phase 2.

[asked] Does the plan end by cutting a release?

Not decided here, by the maintainer's choice: "Let's finish the issues and then we will have this discussion." The plan stops at master. Two things keep until then: ADR-0016 obliges the release notes to name the seven primitives whose values move, and three CHANGELOG-owed lists (09-18, 09-19, 09-20) are queued in TODO.org. Nothing here reaches triage-pg before a tag exists.

[unresolved] Should the target's own read be cut on the as-of date when the target has a temporal index?

Assumption in force: no — PR #43 cuts every non-target read and leaves the target alone, because its rows are the cohort and which of them a date emits is the caller's choice (as_of_dates.id_column). But an event-like target with several rows per id has the same whole-partition windows reading rows after the as-of date, and cutting it would change which rows a date returns, which is a return shape ADR-0015 freezes. Nobody can decide this without numbers, so Phase 6 task 1 measures it and stops. Puts Phase 6 at risk of growing a phase by amendment.

[decided] Order: the name rule before the identifier roles, real width last

Phase 2 changes quote_if_bare, which every site Phase 3 adds goes through; doing them the other way round would write Phase 3's parity tests against a rule about to change. Phase 5 goes after Phase 3 because both edit sharding.py and both move the pinned artifacts. Phase 4 moves no artifact and floats.

[decided] Table names are not quoted

A table value is a relation reference that may carry a schema (analytics.visits, ontology.entities in every triage-pg config). Quoting it whole names no table, and splitting on the dot guesses. Left as written, and documented.

[decided] New classes found by a sweep land as strict xfail, not as a wider PR

Tonight's session is the argument: fixing #27 grew into #36 inside the same PR because the fix could not hold without it, and that was right; #37 and #38 were filed and left, and that was also right. The rule in Phase 6's callout writes the distinction down: same class, fix it here; new class, record it red and amend the plan.

[decided] Phase 6 is split into small test-only PRs

It moves no artifact, so nothing forces it to be serial, and a test-only PR is the cheapest thing to review under the eight-context gate. One PR per task group (future-row, path equivalence, valid-implies-runs, coverage plus the CONTRIBUTING rule).

[decided] The measurement scripts are re-written as tests, not committed as scripts

They live in the session scratchpad and will not survive it. Each phase's first task re-creates its measurement as the committed sweep and re-counts the red before any fix; the counts in this plan are what those re-counts should reproduce on the named commits.
